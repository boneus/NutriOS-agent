# Markdown Health MCP — дизайн

## Цель

Заменить прямые data-tools Health Coach на локальный MCP-сервер поверх Markdown-файлов, сохранив существующие safety-инварианты harness и наглядный контраст между MCP tools и обычными локальными tools.

## Границы

- MCP обслуживает только данные из `data/`: профиль, дневник, рецепты и финальный план.
- Safety Reviewer, scoring, JSON-валидация, rounds и traces остаются в harness.
- `suggestWorkoutTemplate` и `generateShoppingList` остаются локальными tools.
- `append_daily_log` публикуется MCP-сервером, но не выдаётся агентам.
- Внешние серверы и сетевые MCP-транспорты не используются.
- Изменения не коммитятся; тесты не добавляются.

## Подходы

1. Отдельный MCP-процесс для каждой фазы. Просто разграничивает tools, но создаёт лишние процессы и противоречит требованию одного сервера на запуск.
2. Один сервер со всеми tools без фильтрации. Проще, но позволяет drafting-агенту сохранить план до одобрения.
3. **Выбранный:** один stdio-процесс на весь harness-run и динамический `toolFilter` OpenAI Agents SDK. Drafting Health Coach видит только read-only MCP tools, финализатор — только `save_health_plan`, а reviewer MCP не получает.

## Архитектура

`src/mcp/markdownHealthServer.ts` регистрирует пять tools и четыре resources через `@modelcontextprotocol/sdk`, читая пути относительно переданного рабочего каталога. `src/mcp/markdownHealthClient.ts` создаёт `MCPServerStdio`, запускающий сервер через локальный `tsx`, и фильтрует tools по имени агента.

`runHealthAgent` открывает MCP-сессию после валидации входа и закрывает её в `finally`. Один подключённый сервер передаётся двум экземплярам Health Coach: drafting-агенту и финализатору. Существующий сбор `function_call` продолжает записывать имена MCP-tools в общий `toolCalls`.

`scripts/mcpInspect.ts` подключается к тому же серверу, печатает `listTools()` и `listResources()`, затем закрывает процесс.

## Ошибки и безопасность

- `days` ограничивается диапазоном 1–30.
- Пустые `entry` и `markdown` отклоняются схемами.
- Запись дневника добавляет Markdown-блок в конец файла.
- Сохранение плана нормализует завершающий перевод строки.
- Если запуск агента, reviewer или trace завершается ошибкой, MCP-процесс всё равно закрывается.
- `output.md` по-прежнему меняется только финализатором после verdict `approve`.

## Проверка

Без вызовов модели: `npm run mcp:inspect`, затем `npm run typecheck` и `npm run build`. `npm run eval` не запускается автоматически, потому что делает платные DeepSeek-запросы и меняет локальные данные; команда остаётся финальной ручной проверкой Definition of Done.
